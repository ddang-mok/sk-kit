# 목표
핵심 사용 흐름 하나가 실제로 작동하는 상태를 만든다. 화려한 구조보다 평가 가능한 결과가 우선이다.

## 작업 방식
1. 과제 기존 파일과 실행법을 확인하고 수정 범위를 명시한다.
2. 요구된 입력 한 가지에서 기대 출력까지 연결한 뒤, 작은 변경으로 구현한다.
3. 서버라면 시작 로그와 포트, 화면이라면 입력과 버튼 반응, 분석이라면 간단한 검산을 남긴다.
4. 정상 입력 외에 오류·빈 입력 등 중요한 경계 조건을 한두 개 점검한다.

불필요한 프로젝트 전면 개편이나 미승인 API 호출을 하지 않는다. 파일 경로·토큰·비밀번호를 코드에 하드코딩하지 않는다. 실행하지 못한 기능은 구현과 검증 상태를 따로 표시한다.

**완료 보고:** 수정한 파일, 구현된 필수 기능, 실행 명령과 실제 결과, 미완료 목록.
